# The passmcp attestation format

This directory is the part of passmcp meant to be implemented by someone
else. It is licensed **Apache-2.0**, unlike the engine, which is
GPL-3.0-only. A gateway, registry or CI system can read, verify and gate on
a passmcp attestation — or produce a compatible one — without taking on the
engine's licence. [ADR 0011](../docs/adr/0011-attestation-format-is-apache.md)
records why.

The format has two published halves, and only one lives here now:

| Half | Where | Generated from |
|---|---|---|
| The predicate's JSON Schema, and the Go verifier | [passmcp-reporting](https://github.com/sebastienrousseau/passmcp-reporting) — `spec/attestation/` and the `attestation` package | the statement types, by reflection |
| The scoring rubric | [`rubric/rubric-v1.json`](rubric/rubric-v1.json), here | the scorer, by `make spec` |

The verifier moved to its own module, `satellion.com/passmcp-reporting`,
because importing a package from passmcp's module pulls passmcp's whole
dependency graph into a consumer's `go.sum`. `Parse`, `Validate`, `Covers`,
`VerdictFor` and `Compare` are a complete offline verifier for anyone who
would rather embed it than re-implement the schema. The schema moved with
the types it is generated from.

The rubric stays here because it is generated from the scorer, and the
scorer is the one thing it must never disagree with. It moves when the
scorer reads it as data.

## The statement

An in-toto v1 Statement. Its one subject is the evaluated server, and its
digest is over a canonical descriptor of the target — transport plus
address or command — not over an artifact; `predicate.subjectKind` says so
(`mcp-target-descriptor`), and a verifier must check the subject's name
matches the predicate's target. Every field is described in
[passmcp-reporting's docs/format.md](https://github.com/sebastienrousseau/passmcp-reporting/blob/main/docs/format.md).

## The rubric

Each category starts at 100. Every failing or warning finding in its phases
deducts the amount the rubric gives for that outcome, and a category cannot
go below zero. A category counts only if one of its phases ran; the total
is the weight-averaged score of those that did, so a partial run cannot
pass for a full one. The rubric's `version` changes whenever a weight, a
category or the deduction model changes — never for a new check inside an
existing category.

`rubric/rubric-v1.json` is generated by `make spec` and CI fails when it
drifts. Do not edit it by hand.

## Integrity

A verdict asserts only what the run observed. The rubric is public and
versioned so that anyone can recompute a score from the verdicts and get
the same number.
